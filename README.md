# 播浪

中文名：**播浪** · 前缀 `livewave` · 端口 **6400 / 11400**

## 骨架

**互动事件入流 → 事件时间水位线推进 → 热度窗关闭发射 → 迟到修正/撤回 → 窗输出与撤回互证**

皮：直播间点赞/送礼互动。去皮是事件时间窗计算 + 允许迟到与撤回，不是直播运营后台 CRUD，不是点击会话空闲切开。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6400
# 入流 → 灌「准时热度样例」→ 水位线/热度窗 → 再灌「迟到修正样例」看撤回 → 贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 互动事件 | 带事件时/处理时的点赞送礼 |
| 水位线 | 每房一条权威水位（全局时钟口径选定之钟）+ 允许迟到秒；另一钟仅审计 |
| 热度窗 | 翻滚窗；开启累计，关闭发射 |
| 撤回单 | 已关闭窗被允许迟到事件修正 |
| 旁路匣 | 超允许迟到 / 口径漂移失败闭 |
| 窗贯验 | 窗合计 ↔ 事件合计 ↔ 末次撤回 |

## 双钟水位线（时钟口径）

水位推进在**全局选定单一时钟口径**并贯彻到关窗/旁路判定，不得混用：

- **口径=事件时**（默认）：水位=已见最大事件时；处理时仅审计。
- **口径=处理时**：水位=已见最大处理时；事件时仅用于窗键对齐，不得反过来抬水位。

每房水位线只有一列权威「水位」+ 口径戳，关窗/旁路只认它；另一只钟进审计列（`审计事件时`/`审计处理时`），不得另算关窗。只读接口 `GET /api/双钟水位` 返回（房间、水位[按口径即事件时或处理时水位]、口径、valid）。

口径切换**失败闭**：已有流数据（事件/窗/撤回/旁路任一非空）时 `POST /api/口径` 与夹具里的 `尝试切换口径` 一律 409/拒绝，整批仍按原口径执行；仅系统全空时原子切换（站规+全部水位行口径戳同一事务），可整票重放。行内口径戳与全局口径漂移（如越权改库造成的切换半截）时，入流对该房失败闭：不抬水位、不关窗、事件落旁路，`valid=false`。

夹具演示（须先 `docker compose down -v` 清空数据卷再换口径重跑）：

1. 默认事件时口径推「双钟水位样例」：D5（事件时 12:01:30、处理时 12:06:00）不抬水位，落入已关的 12:01 窗发撤回；关窗集合={12:00, 12:01}。
2. 清空卷 → `POST /api/口径 {"口径":"处理时"}`（全空可切）→ 重推同一样例：D5 的处理时抬水位至 12:06:00，关窗集合={12:00, 12:01, 12:02}，D5 自身超迟到旁路。两口径结论可区分。
3. 有数据后推「双钟切换半截样例」：切换请求失败闭，S1 仍按原口径入窗，正式侧只有一套关窗结论。

## 空桩（邻题扩展）
